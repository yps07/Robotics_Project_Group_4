# Environment and data pipeline

## Simulator and coordinate conventions

The source environment is DeepMind Control Suite's `manipulator/bring_ball`
model. The ordinary task remains available with `load_env()` in
`dataset/environment.py`.

Inverse-dynamics data are collected from a reduced model built from the same
`bring_ball` MJCF:

- The four arm hinges (`arm_root`, `arm_shoulder`, `arm_elbow`, `arm_wrist`)
  remain the only generalized coordinates that affect the learned torque
  mapping.
- The four finger/gripper hinges are removed. Their bodies and inertial
  properties remain rigidly attached to the wrist.
- The gripper tendon, coupling constraint, and actuator are removed.
- Collision geoms are disabled for this free-space dynamics dataset. The ball
  is also moved out of the workspace and `ncon` is recorded and required to be
  zero.

This distinction matters: a zero gripper control does not lock the gripper in
the ordinary task, and arm/finger contacts would make a four-coordinate
contact-free model incomplete.

The arm generalized-coordinate order is:

1. `arm_root`
2. `arm_shoulder`
3. `arm_elbow`
4. `arm_wrist`

All four MuJoCo hinge axes are `[0, -1, 0]`; positions are in radians,
velocities in radians/second, and accelerations in radians/second squared.
The unlimited root angle is stored canonically in `[-pi, pi)`. The three
limited arm joints use the MuJoCo ranges with a 0.05 rad rejection margin.

The arm actuators have gear ratios `[12, 8, 4, 2]` and normalized controls in
`[-1, 1]`. The target physical generalized force is taken from
`qfrc_actuator`; for these motor actuators it equals `gear * ctrl`.

## Timebase

The model physics timestep is 0.001 s. One data sample is taken after each
control interval of 0.01 s, which consists of ten physics steps. Excitation
signals use the control timestep, not the physics timestep. Each 1000-sample
episode therefore spans 10 seconds.

Training excitation uses random actions with amplitude 0.35, multi-sines from
0.1 to 1 Hz, and chirps from 0.05–0.2 Hz up to 0.5–2 Hz. OOD excitation uses
amplitude 0.65 and higher sine/chirp frequencies. OOD samples are additionally
filtered so every retained sample has at least one `q`, `qdot`, or `qddot`
component outside the empirical training min/max. All retained samples are
generated by the simulator; inputs are never fabricated by rescaling.

## Dataset schema

Each `data/{train,val,test,ood}.npz` contains:

| Key | Shape | Meaning |
| --- | --- | --- |
| `q` | `(N, 4)` | Arm positions |
| `qdot` | `(N, 4)` | Arm velocities |
| `qddot` | `(N, 4)` | Arm accelerations at the saved state |
| `tau` | `(N, 4)` | Physical arm actuator generalized forces |
| `action` | `(N, 4)` | Normalized arm actuator controls |
| `time_s` | `(N,)` | Sample time within the episode |
| `episode_id` | `(N,)` | Episode number local to the split |
| `mode` | `(N,)` | `random`, `sinusoidal`, or `chirp` |
| `ncon` | `(N,)` | Contact count; must be zero |

`dataset_metadata.json` records the model variant, both timesteps, excitation
settings, split sizes, and episode counts. Samples are spread over independent
episodes (40 for training and 10 for each evaluation split when enough valid
samples are available), rather than taking only a few long-trajectory prefixes.
`stats.json` contains mean/std
statistics computed from the training split only. The PyTorch loader applies
those same statistics to validation, test, and OOD samples.

The NPZ files retain physical `q[4]` values for dynamics and analytical-model
checks. For the black-box MLP, `dataset/preprocess.py` encodes the periodic
root angle as `(sin(q_root), cos(q_root))`; the loader therefore returns
13-dimensional inputs rather than presenting equivalent configurations near
`-pi` and `+pi` as unrelated scalar values. Workstream D can continue to use
the raw physical coordinates and apply its own periodic encoding.

## Reproduction and validation

From the project root, with `dm_control`, MuJoCo, NumPy, and PyTorch installed:

```bash
python -m dataset.inspect_robot
python -m dataset.collect_data
python -m dataset.validate_data
```

Collection writes compressed NPZ files and refreshes training-only scaler
statistics and metadata. Validation checks array shapes and finiteness,
physical/action consistency, joint and acceleration limits, contact counts,
episode time ordering, OOD range separation, and sampled inverse-dynamics
predictions against both `mujoco.mj_inverse` and the analytical model.
